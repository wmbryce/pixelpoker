# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

## Where it runs

Cloudflare, not a server. Client → Pages (static Vite build); game server →
Workers + Durable Objects. Deploy runbook, Pages settings, CI secrets and the
cost model: `docs/cloudflare-deploy.md`. Architecture: `README.md`.

## Commands

`bun install`, then `bun run dev` (wrangler dev :8000 + vite :3000),
`bun run test`, `bun run lint`, `bun run typecheck`, `bun run deploy`.

`server/worker-configuration.d.ts` is generated by `wrangler types` and is
gitignored — the `typecheck` script regenerates it, and CI runs
`bun --filter server types` before typechecking. Fresh clones will not typecheck
until one of those has run.

## Sharp edges

- **One alarm per Durable Object.** The turn clock, AI think-delay, auto-deal and
  AI chat all share it through `server/durable/scheduler.ts`, which keeps due
  events in a SQLite table and parks the single alarm on `MIN(due_at)`. Never
  reach for `setTimeout` in a Durable Object: it dies with the object *and*
  blocks hibernation, which is what keeps the bill at the plan minimum.
- **Storage is authoritative, memory is a cache.** `PokerRoom.persist()` writes
  through to SQLite before touching `cachedGame`. Anything only in a field is
  gone after an eviction, which happens routinely between hands.
- **Stale-alarm guard.** Timers carry a `turnSeq`; a fired timer whose seq no
  longer matches is dropped. Without it, an alarm already in flight when a
  player acts would auto-fold a seat that had already acted.
- **Game logic stays pure.** `server/controllers/` has no I/O and no runtime
  dependencies; the Durable Objects supply the effects. Keep it that way — it is
  why the rules are testable without workerd.
- **Known pre-existing stalls** (carried over from the Express version, not
  introduced by the port): acting during the 4-second showdown window cancels
  the auto-deal and strands the table; if every player times out on the same
  hand the pot is never awarded; and `onGameAction` clears the turn/ai/deal
  timers *before* `processGameAction` validates, so a rejected action (an
  under-minimum raise, or an action for a seat that is not on the clock, which
  is never checked) deletes the alarm and the table waits for a voluntary
  action. All three are reachable in real play.
